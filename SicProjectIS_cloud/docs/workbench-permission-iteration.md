# 部门归属、财务待办与评审工作台迭代

本轮实现 2026-10-11 确认的四项优化，保持现有业务流转与项目授权规则，不新增测试后门、不扩大专家永久项目权限。

## 实现内容

| 问题 | 本轮行为 |
| --- | --- |
| 无部门人员发起申请后无人处理 | Project 在写入项目和 Saga 前读取 IAM 当前身份及部门，只有启用账号且归属启用部门才可申请。旧 JWT 中的部门不作为创建依据；前端禁用无部门账号的申请按钮并提示联系管理员。 |
| 后添加财务人员看不到已有待办 | 财务办理同时要求财务角色与有效项目财务授权。详情展示“等待配置”，管理员可进入项目授权配置；身份与授权变更触发刷新，查询已有任务时重新判断权限，保留原模块和序号。 |
| 工作台只显示未完成流程 | 新增服务端分页查询，支持“全部可见”“我的待办”“我办理过”“已结束”；已结束模块可读，操作按钮遵守当前权限。项目生命周期与模块结束状态分开显示。 |
| 专家提交后项目访问失效，界面体验不清楚 | 新增“我的评审”，分别展示待评审、等待评审开始、已提交等待其他专家、评审已结束、已失效；提交后读取自己的记录，不再依赖通用流程详情。结束后保留自己的评分历史，收回材料和项目临时访问，不显示其他专家评分或批次汇总。 |

历史无部门项目可以由系统管理员或科研管理员在项目授权页面补充部门，必须填写原因。后端加锁后只允许从空部门补充一次，审计与 Outbox 同事务提交，再更新 Workflow 快照。不随负责人后续调部门而自动改变项目归属，不自动修复现有项目。

SSE 增加自动重连、登录 token 变更时替换连接、重新获得焦点和网络恢复刷新、可见页面每 30 秒刷新。通知持久化与实时提示只携带必要的项目或用户 ID，后续查询仍走权限校验。推送丢失不会使新授权永久不可见。

## 接口与使用

- `PUT /api/projects/{projectId}/department`：全局管理员补充历史空部门；请求 `{ "deptId": 1, "reason": "核对后的归属补充" }`。已有部门返回 409。
- `GET /api/workflow-workbench/query`：`view=VISIBLE|TODO|OPERATED|FINISHED`，可选 `moduleType`、`keyword`，`page` 从 1 开始，`pageSize` 最大 100。返回 `items/page/pageSize/hasMore`，按当前权限筛选；历史页不恢复已撤销的项目授权。
- `GET /api/expert-reviews/my-assignments` 及 `/{assignmentId}`：只读当前账号本人的任务和评分记录；即使专家角色后来撤销，自己的历史记录仍可读，提交和材料下载继续单独鉴权。
- 内部增加部门摘要与财务配置查询；旧工作台 `items` 接口保持待办契约。

财务配置顺序：分配 `FINANCE_ADMIN` 角色 → 财务人员重新登录 → 管理员在对应项目授权页添加财务办理授权。模块、轮次或节点限定必须匹配待办；空限定表示授权覆盖该项目。只有角色、没有项目授权时不出现待办。

前端入口：流程工作台切换“已结束”；专家进入“我的评审”。纯专家账号进入旧通用流程页会转到专用评审页。申请时后端仍检查最新部门；分配部门后重新登录以更新前端身份显示。

## 验收与持续集成

本地全量 `mvn -B clean verify` 执行 **218 项测试，零失败、零跳过**；包含真实 MySQL 的部门补充回滚及重复提交、财务授权范围、跨批分页、专家个人记录隔离与历史读取。新增接口契约实际进入测试编译目录，门禁同时核对生成测试是否执行，避免只生成代码却未运行。

前端 `npm test` 的 5 项连接生命周期测试通过，`npm run build` 的类型检查和生产构建通过。浏览器工具连接失败，未将页面视觉或浏览器点击记为已验收。

完整 Gateway 用例启用 `--negative-cases --ui-regression-cases --iteration-regression-cases`，覆盖 37 个用户节点、3 个双专家评审批次和 17 类上传材料。除流程终态外，检查无部门申请零写入、后补财务角色与项目授权、错误轮次授权、已结束流程查询、专家评分隐私、临时权限回收与本人历史。对应数据库核对 29 项业务关系，五库结构检查 52 张表。

CI 增加前端测试与构建任务，前端目录变更触发验证；完整业务任务等待 MySQL 与前端任务通过，启用本轮回归参数。必选回归标志未完成时 runner 不会输出成功报告。远程 CI 和本轮容量/完整故障矩阵尚未执行，不能据此宣称生产环境无死锁。

## 本地构建与配置保护

父模块的 `target` 包含环境凭据、冻结发布包和私有备份，现已从父模块 Maven clean 默认清理目录排除；子模块编译产物仍正常清理。

本轮第一次清理时误删了该目录内部分文件。原凭据从仍在运行的容器恢复，Compose 挂载由当前模块包重建；旧冻结包、部分本地历史日志和历史 SQL 备份无法恢复，数据库卷未清理、现有业务数据未重建。更新服务前重新生成五库备份，私有文件在 `target/localdev-before-workbench/`，不纳入 Git；这份新备份不能替代已丢失的历史备份。

最终应用包冻结于 `target/releases/workbench-final-candidate/`。配置继续使用 `target/local-dev.env` 和 `target/local-dev.compose.yaml`；不重新运行环境准备脚本覆盖已有凭据。服务更新的实际结果以本轮就绪报告为准。

日常 `sic-localdev` 已更新八个应用，Gateway 8080、前端 5173 保持运行；新工作台四种查询与个人评审接口通过原管理员账号读取验证，八个挂载匹配最终冻结包，历史空部门项目未被自动更改。隔离栈 `sic-workbench-20261011` 完成最终包回归后已停止，容器与测试数据保留。完整业务报告记录冻结发布清单摘要，便于核对实际测试版本。
